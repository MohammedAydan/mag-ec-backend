## Design Decisions Already Made (Implicit)

- **Guest carts are server-side persisted** (not signed client tokens). Guest cart lookup uses a `guestToken` string that the client stores and sends. This was chosen because: simpler implementation, works with existing Prisma persistence, and the `guestToken` is opaque to the client (no tampering risk).
- **Cart has both guestToken and userId** (nullable). A cart starts with guestToken, then after merge gets userId and loses guestToken relevance. The merge marks the guest cart as MERGED status.
- **CartItem uses @@unique([cartId, variantId])** to enforce one row per variant per cart, with quantity summed on merge.
- **Wishlist is one-per-user** (userId is @unique on Wishlist). Simple ownership model.
- **WishlistItem uses @@unique([wishlistId, variantId])** — no duplicates.
- **Checkout preview enhancement** is a new CheckoutModule rather than modifying PricingModule directly, to keep pricing preview clean and add stock/reservation as a composable layer.
- **Stock reservation on checkout preview** calls `InventoryCoreService.reserveStock()` in a transaction, using the default warehouse, with a reservation key like `checkout-preview-{cartId}-{timestamp}`.

## Key Integration Points

- `InventoryCoreService.reserveStock(warehouseId, variantId, quantity, reservationKey, expiresAt, userId?, tx?)` — accepts optional Prisma.TransactionClient for transactional reserve
- `InventoryCoreService.releaseStockReservation(reservationKey, tx?)` — release when cart abandoned or reservation expired
- `PrismaTransactionService.runInTransaction(callback)` — wraps multi-step operations
- `PricingPreviewService.previewCheckout(dto)` — existing preview that returns line items, promotions, tax, shipping
- `PromotionEvaluatorService.evaluate(input)` — promotion evaluation
- `CouponNormalizerService.normalize(code)` — coupon code normalization
- `MoneyService` — money arithmetic
- Default warehouse: seeded as `Warehouse` with `isDefault=true`, key `default-warehouse`
